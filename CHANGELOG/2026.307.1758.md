### The build-scope gate found a real defect (fixed in this round)

The seed's only gate was `charly box validate` (structural). The first real build failed in
the guest-kernel step:

```
cp: cannot stat 'config-libkrunfw_amd64': No such file or directory
make: *** [Makefile:145: linux-6.12.109] Error 1
```

**RCA.** libkrunfw's Makefile treats a **non-empty** `ARCH` as the *kernel's* arch spelling
and derives `GUESTARCH := $(ARCH)` (`Makefile:39-56`); with `ARCH` unset it would use
`uname -m` (= `x86_64`). The box bootstrap exports `ARCH=amd64` (the OCI `TARGETARCH`), so
the recipe copied `config-libkrunfw_amd64` — the file is `config-libkrunfw_x86_64` — and the
kernel's own build system would then look for `arch/amd64`. **Missed control:** a structural
gate cannot execute the plan; only a build can. **Blast radius:** every charly-built image of
this candy would fail the kernel step. **Root fix:** map the host arch to the kernel spelling
and export it for the step, so the libkrunfw recipe, `olddefconfig` and `vmlinux` all use it.

A second, consequential defect was fixed with it: a killed/failed build leaves the extracted
tree without the stock `.config`, and the Makefile's directory target then reads "up to date"
and skips the config copy — so the fragment would be appended to an empty `.config`. The step
now forces a clean extract in that state.
